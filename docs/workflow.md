# Workflow and deliverables

The skill is a design collaboration. Approval applies to the artifact shown: approving a character does not approve a different face, pose, palette, or public upload.

1. **Discover:** establish audience, desired outcome, GitHub identity, visual preferences, motion/accessibility needs, and publication limits. Request reference photos, use permission, and LinkedIn link. Collect only what is useful.
2. **Ground:** read public or explicitly authorized LinkedIn content and relevant project sources. If access fails, ask for a permitted export or pasted text. Mark unverified claims for user confirmation.
3. **Design:** show a character sheet with recognizable face views and proposed pose, or an abstract identity board if the user chose no face. Show actual visible swatch boards or small layout previews with hex labels. Record approvals separately; mark portrait-only decisions not applicable for abstract work.
4. **Build:** compose verified copy, editable text, isolated character/background layers, and the approved visual treatment. Produce static artwork first, then optional motion.
5. **Check:** preview at desktop and mobile sizes, check local/remote links, alt text, GitHub rendering, output size, legibility, and a static fallback. Ask the user to resolve material changes before finalizing.
6. **Deliver/publish:** provide a file manifest and preview. Review the exact public inventory and staged diff/upload selection for raw photos, metadata, hidden source layers, private records, exports, and secrets using the skill's [privacy checklist](../skills/github-profile-studio/references/github-delivery.md). Publish only when the current authorization covers the destination and action. Verify the result at the destination; otherwise say what remains local or unverified.

## A fictional project

Mira Vale wants open-source collaborators to notice her documentation tooling. She supplies her own photos and allows a stylized portrait in the public README, but asks that originals stay private. Her supplied career note has no employer or metrics; the profile therefore describes her interests without inventing either. The agent asks for her GitHub and LinkedIn links rather than inventing handles.

She chooses a cream/ink/teal palette after viewing a swatch board, approves a seated character facing the text on the right, and requests gentle motion. The agent keeps editable headline text separate from the portrait, exports a static hero and a small GIF, and presents both. A changed arm pose goes back for approval. Publishing is limited to the README and listed assets in her named repository; private photos are excluded.

## Suggested handoff

Deliver `README.md`, an `assets/` export folder, an editable source folder in a format the user can open, and a short manifest mapping exports to sources. Include dimensions, file sizes, attribution/licenses, verified claim sources, approval status, and the static fallback location. Keep private evidence and raw photos outside public output; redact private source notes before sharing the manifest publicly.
